# 摄像头曝光问题 — 完整排查记录

## 1. 问题背景

### 1.1 硬件环境
| 设备 | 详情 |
|------|------|
| 摄像头1 | HP Wide Vision FHD Camera (cam1, 1024x768) |
| 摄像头2 | HP IR Camera (cam0, 640x480) |
| USB信息 | VID_04CA, PID_7086, Lite-On Technology |
| 驱动 | usbvideo.sys (Microsoft 10.0.19041.6033) |
| 设备栈 | ksthunk → hrdevmon → usbvideo → usbccgp |

### 1.2 现象
- 直接用 OpenCV 打开摄像头，图像非常暗 (mean=13~15)
- 打开 Windows 相机应用后再用 OpenCV，图像正常 (mean=127+)
- 关闭 Windows 相机后，OpenCV 仍能正常工作一段时间
- PowerShell 执行 Disable-PnpDevice/Enable-PnpDevice 后摄像头完全失灵

## 2. 排查过程

### 2.1 第一阶段：基础测试

**测试1：冷启动 vs 热启动**
```
直接冷启动: mean=122.8 (正常!)
再次冷启动: mean=122.5 (正常!)
```
结论：冷启动本身没问题，问题出在"之前被打开过"的场景。

**测试2：Windows相机的影响**
```
Windows相机运行中: OpenCV无法读取 (被占用)
关闭Windows相机后立即测试: mean=-1.0 (读取失败)
等待几秒后测试: mean=122+ (恢复正常)
```
结论：Windows相机关闭后需要等待驱动栈恢复。

### 2.2 第二阶段：参数对比

| 参数 | 正常时 | 暗时 | 说明 |
|------|-------|------|------|
| EXPOSURE | -5.0 | -4.0 | 差异不大 |
| GAIN | 0.0 | 1.0 | 差异不大 |
| BRIGHTNESS | 0.0 | 1.0 | 差异不大 |
| AUTO_EXPOSURE | -1.0 | -1.0 | 相同 |

结论：OpenCV读取的参数值不能解释亮度差异。

### 2.3 第三阶段：设备驱动分析

```powershell
Get-PnpDevice -Class Camera
```
发现设备栈中有 `hrdevmon` — HP的过滤器驱动。怀疑是这个驱动在做特殊初始化。

但进一步测试发现：
- hrdevmon 不是根本原因
- 问题在于 UVC 协议层面的 Auto/Manual 模式标志

### 2.4 第四阶段：深入UVC协议

查阅 UVC (USB Video Class) 规范和 DirectShow 文档，发现关键接口：

**IAMCameraControl 接口：**
```cpp
HRESULT Set(
  long Property,    // 属性类型 (EXPOSURE, FOCUS, etc.)
  long Value,       // 属性值
  long Flags        // 关键! Auto/Manual标志
);

// Flags值:
// CameraControl_Flags_Auto   = 0x0001
// CameraControl_Flags_Manual = 0x0002
```

**关键发现：**
- OpenCV 的 `cap.set(cv2.CAP_PROP_EXPOSURE, value)` 只调用 `Set(Property, Value)` 不传 Flags
- Windows 相机使用 Media Foundation 的 `IMFCameraControl::SetRange()`，正确传递 Auto 标志
- 不传 Flags 时，摄像头默认停留在 Manual 模式

## 3. 验证实验

### 3.1 duvc-ctl 库测试

安装 `duvc-ctl` 库（已封装 DirectShow IAMCameraControl 接口）：

```python
import duvc_ctl as duvc

cam = duvc.find_camera('HP')

# 测试不同模式
cam.set_exposure(-5, 'manual')  # Manual模式
cap = cv2.VideoCapture(0)
ret, frame = cap.read()
print(f"Manual -5: mean={frame.mean():.1f}")  # 22.2

cam.set_exposure(0, 'auto')  # Auto模式
cap = cv2.VideoCapture(0)
ret, frame = cap.read()
print(f"Auto: mean={frame.mean():.1f}")  # 123.0
```

### 3.2 完整测试结果

| 模式 | 设置值 | 实际亮度(mean) | 说明 |
|------|--------|---------------|------|
| Manual | -5 | 22.2 | 最暗 |
| Manual | -4 | 39.1 | |
| Manual | -3 | 48.9 | |
| Manual | -2 | 56.8 | Manual模式极限 |
| Manual | -1 | 57.4 | 无法超过-2 |
| Manual | 0 | 59.8 | 无法超过-2 |
| **Auto** | **0** | **123.0** | **正常亮度!** |

## 4. 根本原因

### 4.1 问题本质
**OpenCV 不设置 UVC Auto/Manual 曝光标志**

Windows 相机使用 `IAMCameraControl::Set(Property, Value, CameraControl_Flags_Auto)`，而 OpenCV 只调用 `Set(Property, Value, CameraControl_Flags_Manual)`。

### 4.2 为什么这样设计

OpenCV 的 DirectShow 后端在初始化摄像头时，不会自动设置 Auto 模式。这是因为：

1. **历史兼容性**：DirectShow 的 VideoProcAmp 和 CameraControl 属性是分开管理的
2. **参数可预测性**：手动模式下参数值更可预测
3. **没有标准接口**：OpenCV 的 `CAP_PROP_*` 常量没有区分 Auto/Manual 的机制

### 4.3 为什么 Windows 相机没问题

Windows 相机使用 **Media Foundation API**，它在枚举和设置摄像头属性时：
1. 正确查询属性范围（包括 Auto 支持）
2. 设置默认 Auto 模式
3. 在后台持续调整曝光

## 5. 解决方案

### 5.1 方案一：duvc-ctl 库（推荐）

```bash
pip install duvc-ctl
```

```python
import duvc_ctl as duvc

cam = duvc.find_camera('HP')

```

### 5.2 方案二：ctypes 调用 IAMCameraControl

需要直接调用 COM 接口，代码复杂度较高，不推荐。

### 5.3 方案三：混合模式

启动时用 duvc-ctl 设置 Auto 模式，之后可以用 OpenCV 的 CAP_PROP_EXPOSURE 调整。

## 6. 经验教训

### 6.1 调试硬件问题的方法
1. **不要假设软件层面没问题** — 驱动和协议层可能有隐藏行为
2. **对比测试** — 找到"能工作"和"不能工作"的差异点
3. **查阅规范** — UVC/DirectShow/Media Foundation 的文档揭示了 Auto/Manual 标志
4. **使用专用工具** — duvc-ctl 封装了底层 COM 接口，避免直接写 ctypes

### 6.2 常见陷阱
- PowerShell 的 Disable/Enable-PnpDevice 不等于 USB Reset，会导致驱动栈混乱
- `libusb`/`pyusb` 无法访问内核驱动占用的设备
- WinRT Python 绑定不稳定，不推荐用于生产

### 6.3 OpenCV 的局限
- `CAP_PROP_*` 常量没有 Auto/Manual 模式的区分机制
- DirectShow 后端不会自动设置 Auto 模式
- 对于需要精确控制摄像头的场景，建议使用专用库
