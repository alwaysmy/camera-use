# MCP 启动行为观察（2026-09-14）

> **起因**：用户发现 camera-use MCP「老被调用」，怀疑"是不是 MCP 加载时就启动摄像头"。
> **排查方式**：临时加 MCP 调用日志（`src/mcplog.go`），记录「谁、何时、调了什么」。
> **结论**：确认是**框架在拉起 MCP 服务器进程**；且此前的确会**顺带打开摄像头**（已修）。
> **处置**：日志功能已于同日移除（内容已提炼进本文），本文保留观察结果与证据。

---

## 一、问题与修复：MCP 加载时打开了摄像头

### 现象

MCP 客户端（Codex / ZCode）启动时，摄像头被打开（指示灯亮），而 agent 可能整轮都不调用相机工具。

### 根因

`backend/src/main.go` 里 `e.Start()` 在 `-mcp` 分支**之前无条件执行**：

```go
e := NewEngine()
if err := e.Start(*codec, *width, *height, !*noIR); err != nil {  // ← 无条件
    ...
}
if *mcp { RunMCP(e); return }                                     // ← 判断在后面
```

→ **每次 MCP 客户端拉起服务器进程，就打开一次摄像头**。

这是「即用即开」改动**没做彻底** —— 当时只改了「不预拉旁路」，漏了 `e.Start()`。

### 修复

`-mcp` 分支提前到 `e.Start()` 之前；相机由 `EnsureOpen()` 在**首次工具调用时懒加载**，
空闲 60 秒自动释放。

### 验证：一个失效的判据（值得记）

| 判据 | 结果 |
|---|---|
| ❌ 「另一进程能否打开相机」 | **失效** —— 实测本机相机**允许多进程共享打开**（HTTP 模式占着相机时，另一进程照样能打开） |
| ✅ 「程序自报状态」 | MCP 启动即打印 `相机 未打开（首次工具调用时懒加载）` ← 决定性 |
| ✅ 辅证（对照 HTTP 模式） | CPU 增量 **0 vs 0.23 秒**、线程数 **6 vs 27** |

### 三个框架的行为差异

| 框架 | 行为 |
|---|---|
| **Codex** | 每次重连**拉新进程，但不清理旧的** —— 实测留下 3 个实例（`05:36` / `06:06` / `06:37`，共 22MB），父进程都是同一个 `codex.exe` |
| **ZCode** | 每次**先拉一个探测进程**（不握手、随后退出），再拉正式的 —— 一次会话拉两个 |
| **DSH** | 观察期内未出现（其 MCP 配置需新会话生效） |

### 资源占用（懒加载生效后，实测）

每个实例：**CPU 增量 0 秒、线程 6、内存 7.3 MB**，且**完全不碰相机** ✓

> 对比修复前：拉起进程即开相机（占设备、亮指示灯、耗电）。现在被遗弃的实例只是静默等待 stdin。

## 三、为什么不改代码去"收拾"被遗弃的实例

**判断：不动。** 理由：

1. **成本已经很低** —— 每个 7.3MB、0 CPU、不碰相机；22MB 可接受
2. **框架的资源清理是框架的事** —— 我们猜它意图有风险：
   - 主动"空闲退出"可能让客户端认为服务器挂了（而它其实还想用）
   - 而**正常的退出路径已经在用**：客户端真退出时会关闭 stdin → `sc.Scan()` 返回 false → 进程自然结束 ✓
3. **实例真堆多了，手动清即可**：

```powershell
# 只杀 1 小时前启动的（避免误杀正在用的）
Get-Process camera_backend -EA SilentlyContinue |
  Where-Object { $_.StartTime -lt (Get-Date).AddHours(-1) } |
  ForEach-Object { "杀 pid=$($_.Id)（启动于 $($_.StartTime.ToString('HH:mm'))）"; Stop-Process -Id $_.Id -Force }
```


**日志字段说明**：

| 字段 | 含义 |
|---|---|
| `caller` | 父进程名（哪个框架拉起的） |
| `client` | MCP 协议 `initialize` 里客户端自报的 name/version |
| `ev` | 事件：start / initialize / tools/list / tools/call / stop |
| `tool` + `args` | 具体工具调用 |
| `pid` / `ppid` | 本进程 / 父进程 |

> `start` 事件发生在 `initialize` 之前，所以那一行的 `client` 为空（还不知道对面是谁）—— 正常。
